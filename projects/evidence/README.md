Everything in this directory is produced by a command, not written by hand. It backs the claims in
[../INDEX.md](../INDEX.md), [../MIGRATION_PLAN.md](../MIGRATION_PLAN.md) and
[../../docs/ARCHITECTURE_ANALYSIS.md](../../docs/ARCHITECTURE_ANALYSIS.md).

## 1. Structural verification (authoritative, always runnable)

```bash
python scripts/verify_projects.py --write-report projects/verification-report.json
```

Result — recorded in [`verification-report.json`](verification-report.json), which also contains the
full path → owner map for every repository file:

```
repository files     : 477   (439 committed application files + 38 files of this decomposition)
owned by one project : 433
shared platform files: 7
excluded portfolio   : 37
projects             : 13
cross-project imports: 45
documented coupling  : 5
RESULT: PASS (0 errors, 0 warnings)
```

What this proves: every file has exactly one owner (or is declared shared/excluded), no ownership
glob is stale, every declared test and interface path exists, the declared dependency graph is
acyclic, and **every cross-project import in `src/` is either a declared dependency or a documented
coupling exception with a named resolution**. Adding undeclared coupling makes the command fail.

## 3. Failure attribution — 101/101 explained, 0 unclassified

[`failure-attribution.txt`](failure-attribution.txt) is generated by
[`scripts/attribute_slice_failures.py`](../../scripts/attribute_slice_failures.py), which classifies
every failing test against the exclusions the repository documents in
[SOURCE_BUNDLE.md](../../SOURCE_BUNDLE.md). Its exit code is non-zero if anything is unclassified —
that is the alarm for "a decomposition or product defect, not the environment".

```
totals by cause
  RESTORED-MEDIA-ABSENT         81
  UPSTREAM-COMMIT-ABSENT        10
  DATASET-SPLITS-ABSENT         10
failing tests attributed: 101
unclassified:             0
```

| Cause | The repository's own statement | Affected slices |
|---|---|---|
| Restored recordings (`data/real_videos/`, `data/test_videos/`, 149 MB) | "**inside the Docker image** at `/opt/sentinelzone/data`" — deliberately not in the source | agentic-supervisor, api-gateway, media-pipeline, hazard-tracking, perception-detection |
| Roboflow splits (`data/roboflow_downloaded/*/`, 29 MB) | "the training images and labels" — not in the source bundle | validation-harness, media-pipeline |
| Upstream commit `bc8e2c88…` | absent from this clone (its `git log` has 8 commits, none of them this one), so the settings-alignment comparison runs against an empty blob | event-contracts, media-pipeline |

**No failure is an ownership, import-boundary or interface error.** Every slice imports and executes
its owned modules, and the same failure classes appear with a minimal dependency set
(`slices-without-torch.txt`) and with the full one (`slices-final.txt`). To reproduce fully green
slices, run them inside the built image, which contains the media:

```bash
docker build -f Dockerfile -t sentinelzone-ai:standalone .
docker run --rm sentinelzone-ai:standalone python scripts/run_tests.py
```
